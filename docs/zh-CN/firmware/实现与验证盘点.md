`pyproject.toml` 将运行时依赖列表留空；dev 组含 ruff、pytest、numpy、h5py。GUI 所需依赖由 `requirements_dashboard.txt`、`requirements_v7.txt`、`requirements_pyqt_gui.txt` 等另列。因此仅安装项目本身不能推定完整 GUI 可运行。

当前 `tests/Makefile` 的 `ALL_TESTS` 展开为 24 个测试目标：7 个链接真实 ADF4382A 源码、6 个 mock/抽取模式、8 个独立逻辑、1 个 STM32 平台、1 个 C++ AGC、1 个 GPS。CI 注释仍称 20 个，属于注释落后，不能据此报当前测试数。

当前 `run_regression.sh` 含 27 处 `run_test` 调用（含 receiver 黄金生成/比较、完整系统和 FT2232H 分支），CI 注释仍称 25 个 testbench。该脚本先执行 lint，再编译/运行并根据输出标记判断；`--quick` 跳过长集成测试。本次未使用 `--skip-lint`。注意该脚本对 vvp 调用的退出状态使用 `|| true`，主要依赖 PASS/FAIL/完成文本；这是一项静态观察，不是实际证明脚本存在误报。

跨层测试源码覆盖静态操作码/位宽/布局，Verilog 联合仿真，以及 C++ stub 设置数据包执行。CI 模式下缺失工具会报错；普通本地模式会跳过部分动态测试。因此未来复跑也需保存跳过数量，不能只记录通过数。

## 文档差异与后续核对

1. `constraints/README.md` 的部分段落写 `USB_MODE` 默认 0，源码实际为 1，200T 构建脚本明确覆盖 0。中文译文保留原文并加核对注。
2. 历史 FT601 操作说明的 `0xAE10xxxx` 包头与当前 `0xAA` RTL 常量不一致。实际 USB 调试需保存烧录 bit、源码 commit、协议版本和抓取字节。
3. MMCM 集成文档中的抖动/裕量为估计或历史说明，不能当成本次测量。
4. 黄金 Hex 文件说明要求流水线改变时重生成；本次未建立生成数据与当前 RTL 的完整匹配证据，未覆盖数据。
5. 本次不修改实现，只增加中文全文资料与核对记录；下一轮验证需要可用 Vivado/Icarus/C++/Python dev 环境以及板卡证据。
